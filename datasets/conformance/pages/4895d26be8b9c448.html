API reference / Rate limiting

Rate limiting

Every endpoint enforces per-key throttling. When you exceed your quota the API responds with 429 Too Many Requests and a set of headers describing your current window.

Response headers

HeaderMeaning
X-RateLimit-Limit Requests allowed in the current window.
X-RateLimit-Remaining Requests left before you are throttled.
Retry-After Seconds to wait before retrying after a 429.

Burst behavior

Limits are smoothed using a TBA Token Bucket Algorithm. Your key accrues tokens at a steady refill rate; each request spends one. A bucket of unspent tokens lets you burst briefly above the nominal limit — up to 2× the per-second rate for ~5 seconds — before throttling kicks in. This is why short spikes succeed but sustained traffic is capped. , so a brief spike can exceed the nominal per-second limit while sustained traffic cannot.

Tip: read Retry-After on every 429 rather than backing off a fixed amount — the value reflects your real refill schedule.
